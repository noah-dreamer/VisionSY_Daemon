# 统一媒体库

VisionSY 以文件目录作为媒体库。宿主机可以先挂载 SMB/NFS 共享，再把照片目录映射到容器；网页上传和目录中已有的文件使用同一套图库、索引、元数据和派生处理。

## 挂载与图库

默认通过 `DAM_HOST_MANAGED` 配置宿主机媒体目录，容器内路径保持 `/data/visionsy/managed` 以兼容已有配置。这个名称不再表示只有新上传原件才能存放在这里。

登记的根目录本身也是一个图库，接收直接放入的文件和默认上传。一级子目录会自动发现为其他图库。根图库只扫描根目录文件，子图库按存储源的递归设置扫描，避免同一文件重复属于根图库和子图库。

在上传页面可以选择任意可写媒体目录及图库，包括扫描发现的已有目录。上传先写隐藏临时文件，再发布完整文件，文件名保留原名并带唯一后缀，避免覆盖同名原件。省略目标时使用默认可写目录的根图库，不再新增无图库归属的 legacy 上传。

历史 `is_managed` 字段保留兼容；新流程的上传、扫描和原件删除能力取决于目录启用状态、写权限和用户权限，不按文件是扫描还是上传进行分类。

## 自动扫描

调度器每分钟为启用的媒体目录派发发现和重扫任务，已经完成扫描的图库也会再次扫描。发现任务和图库扫描任务使用唯一队列锁，图库自身保留扫描锁。

新增文件进入索引；变化的文件更新索引、元数据和预览；消失的原件标记 Missing；再次出现的文件恢复状态。扫描与上传使用相同的后台处理任务。扫描不会改写原件内容。

遍历会剪枝排除任何层级的 `preview/`、旧 `_visionsy/`、隐藏目录、符号链接及配置的排除项。生成文件不会成为图库，也不会被再次索引。

## 图库内预览

例如图库根目录为 `media/`：

```text
media/
├── 已有照片.jpg
├── 上传照片-唯一编号.jpg
└── preview/
    └── 素材ID/
        ├── thumb.jpg
        ├── large.jpg
        ├── watermarked_jpeg.jpg
        └── watermarked_png.png
```

每个子图库的 preview 位于它自己的目录中。数据库 ID 隔离生成文件，因此不同目录中的同名原件不会互相覆盖预览。图库和 preview 的路径均经过容器内根目录边界校验。

新派生统一写入 preview。读取时兼容旧独立派生目录和旧 _visionsy 缓存；后续扫描发现新路径缺少生成文件时会安排重建。新部署只需要挂载媒体目录。

生成预览需要图库内的写权限。逻辑只读的媒体目录禁止上传和删除原件；如果整个挂载也被设置为只读，则只能读取已有缓存，生成新预览会报告写权限错误。

## 测试

使用 `node deploy/docker/test.mjs`。自动化测试数据库和媒体临时目录与站点数据分开，测试不会在 NAS 图库内生成测试素材。
