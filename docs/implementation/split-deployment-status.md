# 当前架构更新：浏览器直连 daemon

Dashboard 已改为纯静态面板，沿用现有页面布局。旧服务端登录、连接存储、代理实现已删除。
静态服务器无凭据卷；浏览器本地账号解锁 AES-GCM 加密的连接配置，管理请求和备份下载直接发到 daemon。
daemon 管理 API 增加来源白名单、预检处理及无 Cookie 的跨域支持。
升级需在各浏览器初始化本地账号并重新添加连接，旧 dashboard_data 卷保留，daemon 数据及现有连接密钥继续有效。
详细配置与当前验证入口见 ../VisionSY_Dashboard/README.md 和 deploy/SPLIT-DEPLOYMENT.md。

本次验证通过：Dashboard Node 测试 5 项；管理 API 测试 20 项、90 个断言（19 项既有 PHPUnit 弃用提示）；
浏览器直连真实请求、错误密钥、来源拒绝、用户 CRUD、异步 SQL gzip 备份下载与删除、离线连接页、刷新/退出解锁；
12 个页面在 6 组桌面尺寸和 2 组手机尺寸通过布局与折叠菜单检查。
两个本机 split-test 容器已更新并健康，彼此无共享 Docker 网络；Dashboard 无挂载卷。
旧生产实例保持原部署。

以下为早期代理式实现历史记录，架构说明以本节为准。

# daemon / dashboard 分体实现与验证

日期：2026-11-10。实现位置：`web/`（daemon）、`dashboard/`（独立控制台）、`deploy/docker/compose.split.yaml`。
使用 Sites 的本地实现流程；本次没有建立或发布云端 Site。

## 已实现

- 普通用户网站、图片/视频传输、缩略图和处理任务继续在 daemon。
- 本机可访问的媒体登录页保持 PlayCaptcha 启用；仅隔离 PHP 自动化测试显式关闭验证码。
- daemon 内 MariaDB 11.4；新增管理密钥与备份记录的增量迁移。
- 独立 Node 控制台，无运行时 npm 依赖；Docker 非 root 用户运行。
- 控制台网页初始化管理员、登录/退出/修改密码、连接配置增删改、多个 daemon 切换。
- IP/域名、协议、端口、API 密钥均在网页填写；可测试连通性及 API 版本。
- 用户、角色、状态、密码、用户组权限与注册默认组管理。
- 媒体目录登记/检查/扫描，图库增删改/扫描/封面设置，素材编辑/删除/预览重建。
- 队列与扫描任务状态，失败任务重试/遗忘，队列平滑重启，操作审计查询。
- MariaDB 异步压缩备份、任务状态、认证下载及删除；输出按流处理，校验写入和最终文件生成。
- 连接凭据仅在添加/编辑 daemon 时填写；每次请求重新检查绑定管理员权限。控制台不提供独立密钥管理。
- 控制台连接密钥加密落盘、登录密码 scrypt、来源与 CSRF 检查、登录限速。
- 缩略图通过短期签名地址从浏览器直接请求 daemon，不经过控制台。
- 新 daemon 关闭原管理页面；旧安装路径和开发测试保留兼容入口。

## 本机验证

隔离项目为 `visionsy-split-test`，两个容器分别连接独立 bridge；没有共同网络、共享业务卷或 Docker socket。
控制台经宿主机发布的 IP/端口完成真实连接。原生产项目未接管，测试媒体目录与数据库均为独立数据。

- 最终 PHP 测试：**201 项、669 个断言全部通过**；测试工具仍有 19 条既有 PHPUnit 弃用提示。
- 控制台后端：**8 项通过**，覆盖独立启动、认证、来源/CSRF、加密持久化、离线管理、代理及兼容性。
- 原安装器：**16 项通过**。
- 真实联调：错误密钥拒绝、所有管理接口、用户/用户组 CRUD、文件扫描及缩略图、备份生成/流式下载/解压内容/删除。
- 故障隔离：daemon 停止时控制台继续工作；daemon 重启后保留数据并重连；控制台停止时媒体网站继续正常响应。
- 浏览器：所有管理页面、用户创建/删除、连接编辑/测试、保存密钥不回显。
- 手机视口 390×844：没有页面横向溢出或浏览器脚本异常。
- 最终代码已构建成两个测试镜像，并重建到本机运行容器；凭据和配置未纳入 Git。

## 边界

本轮验证为同机独立网络、经宿主机地址的联调，尚未在两台物理服务器或公网环境压测。
数据库备份验证为功能与流式传输验证；尚未进行大数据库容量测试或完整灾难恢复演练。
网页暂不提供覆盖运行数据库的恢复操作，也不负责替换自身容器或升级 Docker；`install.sh` 与镜像仓库发布流程后续改造。
NAS 的系统挂载仍由 daemon 主机维护，控制台登记并校验可访问的目录。

## 邮件注册修复

原本机测试配置为日志邮件模式，注册验证码没有投递到真实邮箱。
新增控制台“邮件服务”，支持 SMTP 配置、加密保存授权信息、即时生效及测试邮件。
生产环境未配置真实发信时明确返回提示；发送失败撤销新注册事务，重发失败保留上一条验证码且不增加冷却。
新增 7 项测试覆盖发信关闭、SMTP 异常、注册回滚、重发、显示名冲突及配置授权/脱敏。
本地 SMTP 接收器已验证测试邮件、真实 SMTP 注册邮件与验证码校验全链路，没有使用真实收件人。
控制台邮件配置页、密码不回显和手机布局已通过浏览器检查。
实际对外投递仍需管理员在控制台填入有效的 SMTP 服务及授权信息；测试结束后已恢复原来的邮件配置。
